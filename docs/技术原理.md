# Poly Bridge 预算修改器 · 技术原理

本文说明这个工具**为什么能改预算**：预算在游戏里是哪几个字段、HUD 为什么不自己刷新、
跨进程改内存有哪些底层约束、以及为什么"一次替换几十处"是安全的。

## 1. 目标游戏与环境

| 项目 | 值 |
| --- | --- |
| 包名 / 版本 | `com.drycactus.hq.polybridge`，Poly Bridge v1.2.3 |
| 引擎 | Unity，**Mono 后端**（不是 IL2CPP） |
| ABI | `armeabi-v7a` → 游戏是 **32 位进程** |
| 脚本程序集 | `Assembly-CSharp.dll`（2,477,056 字节） |
| 测试机 | Redmi K40（`M2012K10C`，代号 `ares`），Android 13 / MIUI |
| Root | Magisk 28.1（28100），SELinux `Enforcing`，上下文 `u:r:magisk:s0` |
| 屏幕 | 物理 1080×2400、density 440；游戏强制横屏 → 逻辑 2400×1080 |

**Mono 是这个方案成立的前提。** IL2CPP 会把 C# 编译成机器码，托管层的字段名与调用关系全部消失；
Mono 则把 IL 和元数据完整保留在 `Assembly-CSharp.dll` 里，任何反汇编器都能直接读出来。
所以整条路线的第一步不是"找内存"，而是"读代码"。

## 2. 预算到底是哪几个字段

用自写的 `ildump` 反汇编后可以确定，预算在运行时有**三份副本**。

| 字段 | 类型 | 角色 | 要不要改 |
| --- | --- | --- | --- |
| `LevelParametersScript.budgetAvailable` | `Int32` | **权威来源**，关卡数据里的原始值 | **必须改** |
| `WorldBehaviourScript.budgetAvailable` | `Int32` | 当前关卡运行时的工作副本 | **必须改** |
| `DesktopUIManager.budgetAvailable` | `Int32` | **仅显示缓存**（给 HUD 用的第三份） | 可选 |

关键调用链（反汇编结果）：

```
WorldBehaviourScript.GetTotalBudgetAvailable()  ->  levelParameters.budgetAvailable

WorldBehaviourScript.UpdateBudgetUI():
    UIManager.UpdateBudgetSpent(this.budgetSpent)   // 先刷"已花费"
    UIManager.SetBudget(this.budgetAvailable)       // 再刷"预算"

WorldBehaviourScript.SetBudgetAvailable(int v):
    stfld  budgetAvailable ; call UpdateBudgetUI()  // 赋值后立刻刷 UI

LevelParametersScript.Setup:
    IL_0124   call  WorldBehaviourScript.SetBudgetAvailable(...)   // 每次关卡激活都重灌
```

两条语句的**顺序**很重要：先写"已花费"再写"预算"，而 `SetBudget` 会用
`budgetSpent > budgetAvailable` 判断超预算并给文字上红——所以不管第三份缓存会出现一次性颜色滞后。

最后那行 `Setup IL_0124` 是**最关键的一条**：它意味着
**只改 `WorldBehaviourScript` 而不改 `LevelParametersScript`，
下次关卡激活（重进关卡、读档）时补丁会被原值覆盖回去**。两个字段都要改。

`LevelParametersScript` 的字段顺序是 `levelDescription / vehiclesDescription /`
**`budgetAvailable`** `/ numRoads / numSegments / numSegmentsStrong / numPistons / numRopes /
numCablesStrong / isTutorial / isIntro / isSandbox / hydraulicControllerEnabled /
gradientColorPrefab / editModeCamera / editModeCameraSize / playModeCamera / playModeCameraSize / addAll`。
注意**这是元数据顺序，不是内存偏移**——Mono 会按对齐和实际布局调整，
所以工具没有采用"算偏移直接写"，而是**按数值扫描**，这正是 `patchall` 存在的理由。

## 3. `budgetSpent` 为什么不能改

```
WorldBehaviourScript.GetBudgetUsed()  ->  CalculateTotalSpentMoney()

AreWeOverBudget() => levelParameters.budgetAvailable <= 0 ? false
                        : (levelParameters.budgetAvailable - CalculateTotalSpentMoney()) < 0
```

`GetBudgetUsed()` 是**由场景里的实体重新算出来的**，不是读字段；
`budgetSpent` 只是这个结果的缓存副本。改它没有任何作用，
下一次计算时就会被覆盖，除了让 HUD 短暂闪一下错误数字。

**结论：只改 `budgetAvailable`，不要碰 `budgetSpent`。**

## 4. HUD 为什么不自动刷新

直觉上"改了内存界面就该马上变"，但实测 HUD 一直显示旧数字，直到做一次建造/删除才更新。
原因是：**游戏没有任何定时器或 `Update`/`LateUpdate` 钩子会去调 `UpdateBudgetUI()`。**
`WorldBehaviourScript.OnApplicationPause(bool)` 虽然存在，但它只调用 `SaveToAutoSaveSlot`
做自动存档，从不刷新 UI，而且只在暂停时触发。

`DesktopUIManager.budgetLabel` 是 HUD 预算文字的**唯一写入者**，
而写它的 `UIManager::SetBudget` 在整个程序集里**只有两个调用点**：

```
UIManager::SetBudget  <-  UpdateBudgetUI          IL_001B
                      <-  SwitchToBuildingMode    IL_00D1
```

`SwitchToBuildingMode` 只能从 `CreatorUIManager`（沙盒）进入，
**战役模式没有"从试跑回到建造"的刷新路径**。
`MobileUIManager.budgetLabel` 虽然存在，但交叉引用数为 **0**，是一段死脚本。

### 4.1 已知的刷新触发点

| 触发动作 | 到达 `UpdateBudgetUI` 的路径 | 时机 | 可用性 |
| --- | --- | --- | --- |
| **删除一块已放置的材料** | `RemoveGameObject IL_0203` 直接 `call UpdateBudgetUI` | **同步**、无条件 | ✅ **最省事** |
| 重置（清空设计） | `GUIReset IL_0067` | 同步 | 会毁掉整座桥 |
| 撤销 / 重做 | `Undo IL_022E` / `Redo IL_01ED`，两者都有 `IL_000C brfalse` 提前返回 | 同步 | 仅栈非空时 |
| 新放一块材料 | `ConnectAnchors IL_0386 → UpdateBudgetAfterEndOfFrame` | **延后一帧** | 可用 |
| 拖动锚点 | `AttemptAnchorMoveToPosition IL_01A4`，由 `Update` 每帧驱动 | 每帧 | 需持续拖动 |
| 暂停 / 恢复 App | `OnApplicationPause` 只存档 | — | ❌ 无效 |
| 试跑 / 停止 | 到不了 `UpdateBudgetUI` | — | ❌ 无效 |

所以工具提示用户：**点"应用"之后回游戏随便放一块或删一块材料**。
其中**删除**最可靠，因为它是同步且无条件的。

## 5. 数值显示规则与沙盒陷阱

```
DesktopUIManager.SetBudget(int v):
    if (v > 0)  budgetLabel.text = Localization.Budget + ": $" + String.Format("{0:n0}", v)
    else        budgetLabel.text = "Unlimited"
    this.budgetAvailable = v          // 第三份缓存
```

汇编层面就是 `IL_0001 ldc.i4.0` + `IL_0002 ble` 跳到 "Unlimited" 分支。
**任何 `<= 0` 的值都会被渲染成 `预算: 无限`**，所以面板会拒绝 `0` 和负数；
教学关的预算本来就是 `0`（无限），改它没有意义。
`UpdateBudgetSpent` 把已花费渲染成 `$ 1,234`（有空格、取 `Mathf.Abs`），
并在超预算时把文字变红、`overBudgetPanel.SetActive(true)`。

沙盒 / 创造模式里游戏会**主动把预算覆盖回去**：

```
SwitchToBuildingMode:
    IL_0060   call  UpdateLevelParametersInSandbox
                  ->  CreatorUIManager::GetAmountForResource(0)
                  ->  重新写入两个 budgetAvailable
```

玩家在沙盒里调过资源数量后，游戏会用自己的数值重新盖章，**你打进去的补丁会被静默撤销**。
这不是 bug，是设计如此。还有一个相关地雷：把预算**调低**之后再读一个自动存档，
`CheckForModifiersAfterLoadRoutine` 会判定异常并设 `unlimitedBudget = 1`、
调用 `SetBudgetAvailable(0)`，HUD 变成"无限"。**所以建议只调高。**

## 6. 跨进程内存读写的原理

工具本身是普通 App（`com.pbmod.budget`），通过 `su` 拿到 root 后用标准 Linux 接口读写游戏内存：
`/proc/<pid>/maps` 读可写区域列表（起止地址、权限、映射名），
`/proc/<pid>/mem` 用 `pread`/`pwrite` 在该进程地址空间里按偏移读写。
打开后者需要 `PTRACE_MODE_ATTACH` 权限，普通 App 访问其他 App 进程会被拒绝，
以 root（`u:r:magisk:s0`）打开则通过。`pbmem.c` 因此只保留 `perms[1] == 'w'` 的区域，
并按 **1 MB 分块 `pread`**，在块内用 `memcmp` 找目标 4 字节序列。

**32 位 `off_t` 的静默失败。** 最初扫描只能命中十几个地址，且都在框架区域。
原因是 32 位 Android 默认 `off_t` 是**32 位有符号**，
`pread(memfd, buf, len, (off_t)addr)` 在地址超过 2 GB 时**静默失败或截断**——
不报错，只是读不到。而 Unity 的托管堆正好在 2 GB 以上。

```c
#define _FILE_OFFSET_BITS 64
#define _LARGEFILE64_SOURCE
```

一个 `#define`，命中数从 **16 涨到 96**。

**分块失败不能 `break`。** `/proc/<pid>/mem` 里存在读不出来的空洞（未映射页），
这是常态而非异常。原代码在某个 1 MB 分块失败时直接 `break`，
导致**该区域剩下的部分全部放弃扫描**。改成跳过一页继续并单独计数：

```c
ssize_t got = pread(memfd, buf, want, (off_t)addr);
if (got <= 0) { chunks_fail++; addr += 4096; continue; }
```

## 7. 4 字节对齐为什么是必须的

整数在内存里是 4 字节。如果按**字节**滑动一个 4 字节窗口：

```
地址:   0x1000 0x1001 0x1002 0x1003 | 0x1004 0x1005 0x1006 0x1007
内容:   0x01   0x00   0x00   0x00   | 0x00   0x02   0x00   0x00
字段:   └────── A = 1 ──────────┘   └────── B = 512 ───────┘
                    ↑  在 0x1001 处读 4 字节 = 0x00000000 = 0
```

未对齐位置也会匹配到数值（这里是 0），一旦写下去就会**同时破坏 A 和 B 两个字段**。
实测证据：加对齐过滤前后，同一个值的命中数从约 **96 降到 46**，少掉的正是这些假命中。
修复（`scan_value` / `patchall` / `pair` / `patch` 四处都要）：

```c
/* 只看绝对地址 4 字节对齐的窗口 */
if (((addr + (uint64_t)o) & 3) != 0) continue;
```

注意判断的是**绝对地址**而非块内偏移：区域起点页对齐、分块 1 MB 是 4 的倍数，
所以块边界永远不会把一个对齐的 int32 切成两半。

## 8. `patchall` 的策略

游戏在扫描期间一直在跑，内存随时在变。处理步骤：

1. **先收集，后写入。** 第一遍只把地址收集进数组；边扫边写会破坏后续扫描依赖的数据。
2. **跳过文件映射区域。** 映射名以 `/` 开头的是**被 mmap 进来的真实文件**（`.so`、资源），
   不是活跃变量；往里面写会脏页缓存甚至损坏磁盘文件。
   实测一次运行会跳过 **847** 个这类区域：

   ```c
   if (regions[i].name[0] == '/') { skipped_regions++; continue; }
   ```

3. **逐个重新读、只写这 4 个字节。**

   ```c
   uint32_t now = 0;
   if (read_value(at, &now) != 0 || now != a) { raced++; continue; }  // 值变了就放过
   if (write_value(at, newv) == 0) hits++; else wfail++;
   ```

   这修掉了一个很隐蔽的 bug：早期版本把整个 1 MB 分块 `pwrite` 回去，
   会**把游戏在扫描期间对该分块做的所有并发修改一起回滚**，还可能撕裂数值。
   另外 `write_value` 现在循环直到 4 字节写完（`/proc/pid/mem` 按页操作，短写必须补齐）。

输出格式（App 侧用正则 `replaced\s+(\d+)\s*,\s*write-failures\s+(\d+)` 解析，
**只有 `replaced > 0` 且 `write-failures == 0` 才算成功**，这修掉了
"只要输出里出现 `patchall` 字样就报成功"的假成功提示）：

```
patchall 10000 -> 999999 : replaced 46, write-failures 0, file-backed regions skipped 847
```

## 9. 为什么"替换 46 处"是安全的

1. **它们都是同一个数值的副本。** 命中 46 处，是因为同一个"当前预算"在托管堆上
   按值存在多份拷贝（实时值、缓存、装箱副本、各对象里的沉淀值）。
   它们**本来就应当相等**，改成同一个新值不会制造出本不该存在的不一致。
2. **权威字段也被覆盖到了。** `LevelParametersScript.budgetAvailable` 必然在命中集合里，
   所以第 2 节说的"关卡激活时覆盖回去"不会发生——下次 `Setup IL_0124` 灌进去的就是新值。
3. **派生量自洽。** `budgetSpent`、`GetBudgetUsed()`、`AreWeOverBudget()` 全部由场景实体重算，
   不依赖这些字段的旧值，改完游戏自己会把一切对齐。

真机实测：关卡 1-3 里 `patchall 10000 -> 999999` 返回 `replaced 46, write-failures 0`，
游戏继续正常运行；随后删掉一块材料触发 `UpdateBudgetUI`，HUD 立刻显示 `预算: $999,999`。
**两条边界：** 只调高不要调低（见第 5 节）；改动**只在内存、只在当前关卡、
只在当前这次游戏会话**有效，退出游戏即恢复，存档文件一个字节都不会被修改。

## 10. 小结

| 问题 | 结论 |
| --- | --- |
| 改哪个字段 | `WorldBehaviourScript.budgetAvailable` **和** `LevelParametersScript.budgetAvailable` |
| 不要改哪个 | `budgetSpent`（由实体重算）；`DesktopUIManager.budgetAvailable` 可不改（仅颜色滞后） |
| 值的约束 | 必须 `> 0`，否则显示 `Unlimited` |
| 怎么找、怎么写 | 按数值扫描，只扫 4 字节对齐窗口；逐地址重读确认后单字写入，跳过文件映射区 |
| HUD 何时更新 | 不会自动更新；删掉一块材料是最省事的触发方式 |
| 生效范围 | 当前关卡 + 当前会话，仅内存，不动存档 |
