# Poly Bridge (Mono) — budget/HUD refresh analysis

Source: full IL dump of `managed/Assembly-CSharp.dll` (456,413 lines, every method).
Tool note: the built binary's real arg order is `ildump.exe <dll> <mode> <regex>`, not `ildump.exe list <dll>`;
`il` mode takes a **regex** matched against `Type::Method`, so `"A::B|C::D"` is regex alternation.

## Fields to patch

Confirmed: **two fields are required, and the claim is correct** — plus one optional display cache.

1. `WorldBehaviourScript.budgetAvailable` — the value the HUD prints. `UpdateBudgetUI` reads it at `IL_0016 ldfld WorldBehaviourScript::budgetAvailable` and passes it to `UIManager::SetBudget`.
2. `LevelParametersScript.budgetAvailable` — the authoritative copy: `LevelParametersScript::Setup IL_011F` reads it and calls `WorldBehaviourScript::SetBudgetAvailable` (which does `stfld` + `UpdateBudgetUI`). Also used by `AreWeOverBudget` (`IL_0006`, `IL_0019`), `GetDescriptionBudget` (`IL_0001`, `IL_001C`), `AllEventsComplete` (`IL_00C7`, `IL_00D7`) and `CheckForModifiersAfterLoadRoutine` (`IL_0081`, `IL_0092`). Patch this or the value reverts on next level (re)activation.
3. *(optional)* `DesktopUIManager.budgetAvailable` — a third cached copy, written only by `SetBudget` (`IL_005F–IL_0061 stfld`). It is display-only (over-budget colour test in `UpdateBudgetSpent IL_0037/IL_0044`). It self-heals on the same refresh, but see the lag note below.

`WorldBehaviourScript.budgetSpent` / `DesktopUIManager.budgetSpent` are recomputed by `CalculateTotalSpentMoney` before every refresh — do not patch them.

## Automatic refresh

**No.** There is no timer, no `Update`/`LateUpdate`/`FixedUpdate` hook, no focus/pause handler that touches the budget.
- `WorldBehaviourScript::Update` contains no `UpdateBudgetUI` call; its only budget path is the anchor-drag described above.
- `WorldBehaviourScript::LateUpdate` only maintains `liveStressValues` → `DesktopUIManager::SetHighestStress`.
- `WorldBehaviourScript::OnApplicationPause(bool)` = `IL_0006: call SaveToAutoSaveSlot` and nothing else — **pause/resume does not refresh the HUD**. `IL_0000: ldarg.1` / `IL_0001: brfalse` = only on pause, never on resume.

Implication for the overlay: after patching, nothing happens on screen until the player acts. Do not rely on resume.

## Other label writers / risks

- `DesktopUIManager.budgetLabel` is referenced **only** at `DesktopUIManager::SetBudget IL_0008` and `IL_003C` — the sole writer of the HUD budget text in the whole assembly. No localization refresh, no `OnEnable`, no `MobileUIManager` path rewrites it (`MobileUIManager.budgetLabel` has zero xrefs — dead).
- `UIManager::SetBudget` (`IL_0007 callvirt DesktopUIManager::SetBudget`) has exactly two callers: `UpdateBudgetUI IL_001B` and `SwitchToBuildingMode IL_00D1`.
- **Colour lags one refresh**: `UpdateBudgetUI` runs `UpdateBudgetSpent` *first* (`IL_000B`), which compares `budgetSpent` against the *old* `DesktopUIManager.budgetAvailable`, then `SetBudget` updates it. Raising the budget leaves the red text/`overBudgetPanel` on until a second refresh — unless you also patch `DesktopUIManager.budgetAvailable`, or the user triggers two refreshes.
- Any value `<= 0` renders `Localization.Budget + ": " + Localization.Unlimited` (`SetBudget IL_0001 ldc.i4.0`, `IL_0002 ble`).
- Level-description panel is a *different* label (`LevelDescriptionPanel.descriptionBudget` via `GetDescriptionBudget`) and keeps the pre-patch number until the intro is rebuilt (`UpdateLevelDescriptionUI` is called only from `ActivateLevel IL_019C` and `EaseIn`).
- Sandbox/creator mode: `SwitchToBuildingMode IL_0060 → UpdateLevelParametersInSandbox` re-stamps both `budgetAvailable` fields from `CreatorUIManager::GetAmountForResource(0)` (`IL_004B–IL_0050`, `IL_0061–IL_0066`), silently undoing a patch.
- Lowering the budget then loading an autosave can trip `CheckForModifiersAfterLoadRoutine` → `unlimitedBudget = true`, `SetBudgetAvailable(0)` → "Unlimited".

## Recommended user-facing procedure

1. Patch `WorldBehaviourScript.budgetAvailable` **and** `LevelParametersScript.budgetAvailable` with the same int `> 0`; ideally `DesktopUIManager.budgetAvailable` too (fixes the colour in one shot).
2. Trigger a refresh with the cheapest guaranteed action: **delete one placed piece** (select it → trash). One tap, synchronous, HUD repaints in the same frame with the new total.
   - No piece on screen? Draw one segment between two anchors (refreshes next frame), or Undo, or Reset.
   - Do **not** use Play/Stop as the refresh step — `StartSimulation`/`StopSimulation` never reach `UpdateBudgetUI`, and the campaign "back to build" path does not exist (only the sandbox one does).
3. If the red "over budget" styling is wrong after the first action, do one more delete/undo (or patch `DesktopUIManager.budgetAvailable`) — that is the one-refresh lag described above.
